# بوت «فني»

بوت تلغرام يربط العملاء بمهنيين وفنيين موثوقين، بنظام تسجيل ومراجعة، وبحث بالمهنة/المدينة/الحي مع تناوب عادل بالظهور.

## المتطلبات

- Python 3.10 أو أحدث
- توكن بوت تلغرام (من [@BotFather](https://t.me/BotFather))
- رقمك الرقمي بتلغرام (من [@userinfobot](https://t.me/userinfobot)) — يُستخدم كأدمن للموافقة على تسجيلات الفنيين
- (اختياري لكن موصى فيه) كلمة مرور تختارها للوحة تحكم الويب

## التشغيل (خطوة بخطوة)

```bash
# 1) تثبيت المكتبات المطلوبة
pip install -r requirements.txt

# 2) إعداد متغيرات البيئة
cp .env.example .env
# افتح .env وضع فيه:
#   BOT_TOKEN=توكن_البوت_من_BotFather
#   ADMIN_TELEGRAM_ID=رقمك_من_userinfobot
#   TAP_SECRET_KEY=مفتاح_Tap_السري (اختياري لحد ما تفعّل الدفع عبره)

# 3) تشغيل البوت
python main.py
```

لو كل شي تمام بترى بالطرفية: `بوت «فني» يعمل الآن (polling)...` — افتح البوت بتلغرام وجرّب `/start`.

قاعدة البيانات (`fani_bot.db`) تُنشأ تلقائيًا بأول تشغيل — ملف SQLite واحد، ما يحتاج أي إعداد خارجي.

## لوحة تحكم الأدمن (صفحة ويب)

صفحة ويب منفصلة (لكن تقرأ/تكتب نفس ملف قاعدة البيانات مباشرة) لإدارة الفنيين والاشتراكات والمهن والإعدادات، بدون أي أوامر بوت أو Mini App.

```bash
# لازم تحط كلمة مرور باللوحة قبل التشغيل (بنفس ملف .env):
#   ADMIN_PANEL_USERNAME=admin
#   ADMIN_PANEL_PASSWORD=كلمة_مرور_قوية_تختارها

python admin_panel/app.py
```

بعدها افتح `http://127.0.0.1:5050` بالمتصفح (أو دومين/عنوان السيرفر إذا كانت مستضافة، مع فتح المنفذ 5050 أو ربطه بـ Nginx). شغّل هذا الأمر بجانب `python main.py` (بعملية منفصلة) — البوت واللوحة يشتغلون بنفس الوقت ويشتركون بنفس قاعدة البيانات.

**صفحات اللوحة**:
- **الرئيسية**: إحصائيات عامة — عدد الفنيين لكل حالة، عدد المشتركين، ضغطات واتساب، عمليات البحث، إيرادات Tap المدفوعة، عدد اشتراكات Stars، وأكثر المهن/المدن طلبًا.
- **الفنيون**: قائمة قابلة للفلترة (الحالة، المدينة، المهنة، الاشتراك، بحث بالاسم/الرقم) مع ترقيم صفحات، وأزرار قبول/رفض سريعة، وصفحة تفاصيل لكل فني فيها: تعديل بيانات التواصل، تفعيل/إلغاء الاشتراك يدويًا مع تاريخ انتهاء اختياري، تصفير عداد الفرص المجانية، وحذف نهائي.
- **الاشتراكات والمدفوعات**: سجل كل الدفعات (Tap و Stars) مع اسم الفني وحالتها (معلّقة/مدفوعة)، قابل للفلترة.
- **المهن**: إضافة/تعديل/حذف المجالات والمهن (مع كود ISCO والخدمات الفرعية) — أي تغيير هنا ينعكس فورًا بالبوت (شاشتي التسجيل والبحث) بدون إعادة تشغيله، لأن بيانات المهن انتقلت من ملف JSON ثابت لقاعدة البيانات نفسها.
- **الإعدادات**: تعديل سعر الاشتراك (ريال ونجوم)، مدة الاشتراك بالأيام، وعدد الفرص المجانية — تُطبّق فورًا على البوت.

**ملاحظات أمان مهمة**:
- بدون `ADMIN_PANEL_PASSWORD` باللوحة ترفض التشغيل تمامًا (حماية من نسيان كلمة المرور).
- لو نشرت اللوحة على الإنترنت (مو بس على جهازك)، تأكد تستخدم HTTPS (عبر Nginx/Caddy مثلًا) عشان كلمة المرور ما تنرسل بنص واضح.
- الجلسة (تسجيل الدخول) تُبنى على `ADMIN_PANEL_SECRET_KEY`؛ لو تركته فاضي، يتولّد مفتاح عشوائي بكل تشغيل، فتسجيل الدخول ينتهي تلقائيًا عند إعادة تشغيل اللوحة (طبيعي، مو خطأ).

## هيكل المشروع

```
fani-bot/
├── main.py                  # نقطة التشغيل — يربط كل الهاندلرز
├── config.py                # قراءة متغيرات البيئة (BOT_TOKEN, ADMIN_TELEGRAM_ID, إعدادات الدفع)
├── db.py                    # طبقة قاعدة البيانات (SQLite) + منطق التناوب العادل والفرص المجانية والاشتراك
├── tap_client.py             # عميل Tap Payments (إنشاء شحنة + التحقق من حالتها)
├── professions_repo.py      # تحميل بيانات المهن (professions.json) ودوال بحث عليها
├── data/
│   ├── professions_source.xlsx      # ملف المهن الأصلي (65 مهنة) — يُستخدم مرة وحدة فقط للبذر الأول
│   ├── build_professions_json.py    # يحوّل الإكسل إلى professions.json
│   └── professions.json             # يُستخدم فقط لبذر قاعدة البيانات أول تشغيل (راجع professions_repo.py)
├── handlers/
│   ├── start.py              # /start
│   ├── register.py           # /register — تدفق التسجيل الكامل (7 خطوات)
│   ├── search.py             # /search — بحث العميل + التناوب العادل + زر واتساب
│   ├── admin.py              # إشعار الأدمن وزري قبول/رفض
│   └── subscription.py       # /subscribe — الدفع عبر Tap أو Telegram Stars
├── admin_panel/
│   ├── app.py                 # لوحة تحكم الأدمن (Flask) — تشغيل منفصل: python admin_panel/app.py
│   ├── templates/              # صفحات HTML (تسجيل دخول، رئيسية، فنيون، مدفوعات، مهن، إعدادات)
│   └── static/style.css        # تصميم بسيط، من اليمين لليسار
├── requirements.txt
└── .env.example
```

## الأوامر المتاحة للمستخدم

| الأمر | الوظيفة |
|---|---|
| `/start` | القائمة الرئيسية |
| `/register` | التسجيل كفني |
| `/search` | البحث عن فني |
| `/subscribe` | تفعيل/تجديد الاشتراك (للفنيين النشطين فقط) |
| `/cancel` | إلغاء أي عملية جارية (تسجيل أو بحث) |
| `/help` | عرض قائمة الأوامر |

## أهم القرارات التصميمية (ليه بُني كذا)

- **قاعدة بيانات SQLite**: ملف واحد بدون أي حساب خارجي أو إعداد — أبسط خيار ممكن لحجم المشروع الحالي. لو احتجت لاحقًا تنتقل لقاعدة بيانات أقوى (لما يكبر عدد الفنيين كثير)، التحويل من SQLite لأي قاعدة SQL ثانية سهل نسبيًا.
- **بيانات المهن الآن بقاعدة البيانات (جدولا `domains` و`professions`)، مو ملف ثابت**: `data/professions.json` (المبني أصلًا من الإكسل عبر `build_professions_json.py`) يُستخدم فقط لبذر القاعدة تلقائيًا أول مرة تشتغل فيها البوت أو اللوحة (`db.seed_professions_from_json_if_empty`) — بعد هذي المرة، أي تعديل على المهن يصير حصرًا من لوحة التحكم (صفحة "المهن")، وينعكس فورًا على `/register` و`/search` بدون إعادة تشغيل البوت. تعديل ملف الإكسل/JSON لاحقًا ما له أي تأثير.
- **التناوب العادل**: كل فني له عدّاد `times_shown` بقاعدة البيانات. ترتيب نتائج البحث = الأقل ظهورًا أولًا (`times_shown ASC`)، وعند التساوي يُستخدم ترتيب عشوائي — هذا يمنع أي تحيّز ثابت لصالح فنيين معيّنين (تم اكتشاف هذا التحيّز فعليًا أثناء الاختبار وإصلاحه، راجع قسم "الاختبار" بالأسفل).
- **الفرص المجانية**: كل فني له عدد فرص مجانية (افتراضيًا 3، وقابل للتعديل فورًا من لوحة التحكم → الإعدادات) — كل ضغطة "تواصل واتساب" من عميل مختلف تُحسب فرصة. بعد استهلاكها، الفني يختفي من نتائج البحث تلقائيًا إلا إذا كان مشتركًا (عبر الدفع أو تفعيل يدوي من اللوحة).
- **رقم الواتساب مخفي خلف زر**: بطاقة الفني بنتائج البحث ما تعرض رقم الواتساب مباشرة — لازم العميل يضغط "📱 تواصل عبر واتساب" أولًا، وهذا بالضبط لحظة تسجيل الضغطة واستهلاك الفرصة المجانية. رقم التلغرام يظهر مباشرة بالبطاقة (غير محسوب من الفرص المجانية).
- **الدفع بطريقتين، وكل وحدة لها دور مختلف**: تلغرام يشترط Stars لأي "خدمة رقمية تُستهلك داخل تلغرام" — واشتراك الفني لتجاوز الفرص المجانية هو بالضبط هذا النوع، فـStars موجود كخيار متوافق 100% مع شروط تلغرام. لكن غالبية الفنيين المستهدفين يستخدمون مدى وما يملكون طريقة سهلة لشراء Stars (تحتاج بطاقة دولية أو عملة رقمية)، فأضفنا Tap كخيار ثاني يدعم مدى/فيزا/آبل باي مباشرة. **تنبيه مهم**: الدفع عبر Tap لنفس هذي الخدمة (الاشتراك داخل البوت) يقع بمنطقة رمادية من ناحية شروط تلغرام الحرفية (التفاصيل الكاملة ناقشناها بالمحادثة) — احتمال إنفاذ فعلي من تلغرام ضعيف لبوت صغير محلي، لكنه مو معدوم. هذا قرارك وتحمّلت مخاطره بوعي.
- **تدفق Tap بدون سيرفر webhook منفصل**: بدل ما نحتاج رابط عام يستقبل إشعارات Tap تلقائيًا (يحتاج استضافة إضافية)، الفني نفسه يضغط زر "✅ تحققت من الدفع" بعد ما يدفع، والبوت يسأل Tap API مباشرة عن حالة الشحنة. أبسط للبداية، لكن يعني الفني لازم يرجع للبوت يدويًا بعد الدفع (مو تفعيل تلقائي فوري).

## ملاحظة مهمة — التشغيل المستمر (Hosting)

هذا الكود يشتغل بأسلوب "polling" (يسأل تلغرام باستمرار عن رسائل جديدة)، وهو أبسط أسلوب للتطوير والتجربة. عشان يفضل شغّال 24 ساعة حتى لو قفلت جهازك، تحتاج تشغّله على سيرفر أو خدمة استضافة بسيطة (مثل Railway أو Render أو VPS صغير). على نفس السيرفر، شغّل `python main.py` (البوت) و`python admin_panel/app.py` (اللوحة) كعمليتين منفصلتين — كلاهما يقرآن/يكتبان نفس ملف `fani_bot.db`.

## اختبار تم إجراؤه فعليًا (بدون إنترنت/توكن حقيقي)

بيئة التطوير الحالية ما تقدر توصل لـ PyPI لتثبيت مكتبة `python-telegram-bot`، فالاختبار الفعلي صار على طبقة قاعدة البيانات ومنطق التناوب مباشرة (بدون الحاجة لتلغرام نفسه)، وعلى ربط الهاندلرز عبر نسخة مبسّطة (stub) من مكتبة تلغرام. تم التأكد من:

- صحة بيانات المهن (65 مهنة، 17 مجال) وسلامة تحويلها من الإكسل
- تقسيم نتائج البحث لصفحات (5+) بدون تكرار أو فقد نتائج بين الصفحات
- **عدالة التناوب فعليًا**: محاكاة 20 عملية بحث لنفس المهنة/المدينة أظهرت توزيعًا شبه متساوٍ (14-15 ظهورًا لكل فني من أصل 7) بعد إصلاح خطأ كان يسبب ظهور 3 فنيين فقط بكل مرة
- اختفاء الفني تلقائيًا بعد استهلاك 3 فرص مجانية، ورجوعه بعد تفعيل الاشتراك (اختبرنا التفعيل مباشرة بقاعدة البيانات بنفس الدوال اللي يستخدمها كل من مسار Tap ومسار Stars)
- ربط كل الهاندلرز الـ13 بـ `main.py` بدون أخطاء استيراد، وعدم تعارض أي نمط أزرار (callback_data) بين `/register` و `/search` و `/subscribe`
- منطق الدفع بقاعدة البيانات (إنشاء دفعة pending، ربطها بـ charge id، تحويلها لـ paid، تفعيل الاشتراك) لكل من Tap وStars
- هجرة بيانات المهن لقاعدة البيانات: البذر الأول (17 مجال/65 مهنة مطابقة تمامًا لـ IDs الملف الأصلي)، عدم تكرار البذر بتشغيل ثاني، إضافة/تعديل/حذف مجال ومهنة وظهورها فورًا عبر `professions_repo`، وحماية الحذف (مجال فيه مهن، أو مهنة عندها فني مسجّل) من الحذف الخاطئ
- **لوحة تحكم الأدمن بالكامل، فعليًا عبر Flask test client (طلبات HTTP حقيقية على السيرفر، مو محاكاة)**: تسجيل الدخول (نجاح/فشل)، الحماية من الوصول بدون تسجيل دخول أو بعد تسجيل الخروج، صفحة الإحصائيات، فلترة وترقيم صفحات قائمة الفنيين (مع أكثر من 20 فني)، قبول/رفض فني، تعديل بياناته، تفعيل/إلغاء الاشتراك يدويًا، تصفير الفرص المجانية، حذفه نهائيًا، فلترة صفحة المدفوعات، حفظ الإعدادات وانعكاسها فورًا بقاعدة البيانات، وإدارة المهن (إضافة/تعديل/حذف مجال ومهنة، مع رفض الحذف عند وجود ارتباط)

**لم يُختبر بعد** (يحتاج تشغيل حقيقي على جهازك بتوكن حقيقي ومفتاح Tap حقيقي): سلوك أزرار تلغرام الفعلية، زر "مشاركة رقم التلغرام"، عملية الدفع الفعلية بصفحة Tap واستدعاء API الحقيقي، فاتورة Stars الفعلية داخل تطبيق تلغرام، وتجربة المستخدم الكاملة من الموبايل. جرّب كل مسار دفع بحساب حقيقي قبل ما تعتمد عليه فعليًا مع فنيين حقيقيين.
